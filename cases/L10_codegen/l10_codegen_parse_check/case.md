# 场景

用 `text/template` 按随机配置渲染一份 Go 源码文本（多个 Item struct、每字段 getter、Status 枚举、Service 接口与实现、Dispatch switch），随后用 `go/format` 规范化、`go/parser` 建 AST、`go/types` 做完整类型检查，并通过 AST 计数与 `types.Package` 作用域/方法集断言生成结果的结构。另注入语法错误与类型错误，确认 parser/types 能拒绝。

## 期望行为

1. 模板渲染成功，两次渲染逐字节一致，首行为 `// Code generated by l10gen. DO NOT EDIT.`；
2. `go/parser` 成功解析，AST 中 struct 数量 = Item 数 + 1（impl），func 数量 = 每类型（字段数+3）+2；
3. `go/types` 全量检查通过；每个 Item 的字段数、GetName/Init/各字段 getter 均存在；Status 常量值正确；Service 方法数 = Item 数；Dispatch 存在；
4. 追加 `func broken( {` 被 parser 拒绝；追加 `var x int = "str"` 与未定义类型均被 types 拒绝；
5. GC 后重新渲染同输入，源码逐字节不变且仍通过类型检查；
6. 另外 3 个 `UAF_SEED` 派生配置生成不同规模的源码，全部通过 parser/types；
7. 最后一行 `ALL PASS l10_codegen_parse_check`。

## 失败判读

- 模板渲染失败/输出不稳定：模板在 range 内误用了外层变量（本用例曾覆盖该缺陷形态）；
- parser 拒绝合法源码：生成文本语法错误（缺换行/尾逗号等）；
- types 报 undefined/类型不匹配：生成器名字冲突或字段类型表错误；
- 负例未被拒绝：parser/types 未被真正调用或错误被吞掉；
- `requires: [goast]`：内网无 go/parser、go/types 的构建可用 `CAPS` 跳过本用例。

## 参数

- `UAF_SEED`：Item 数量/字段数量/字段类型组合的种子，失败输出带 seed。

## 运行

```bash
go build -o /tmp/case ./cases/L10_codegen/l10_codegen_parse_check/*.go
UAF_SEED=1 GODEBUG=clobberfree=1 /tmp/case
```
