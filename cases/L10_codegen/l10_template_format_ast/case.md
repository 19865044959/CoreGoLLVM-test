# 场景

用 `text/template` 按配置渲染一份完整 Go 源文件（`//go:generate` directive、N 个带 doc 注释的 struct、struct tag、每类型一个方法），先故意加厚缩进，再交给 `go/format.Source` 归一化，然后用 `go/parser`（`ParseComments|AllErrors`）建 AST，校验声明数量、字段名/类型/tag、方法接收者、doc 注释、weight 字面量与 directive 位置；并用 `format.Node` 回印 AST，要求与 gofmt 输出逐字节一致。GC 后复核保留的 AST 与源码。

## 期望行为

1. 同一配置两次渲染逐字节一致，首行为 `// Code generated by l10gen. DO NOT EDIT.`；
2. `format.Source` 成功且幂等；输出以换行结尾、无行尾空白；未格式化输入经 gofmt 后与规范输出一致；
3. `go/parser` 解析成功，type 声明数 = 方法数 = 配置类型数；每个 struct 字段数、字段名、`json:"..."` tag 与配置一致；每个方法为指针接收者且 weight 字面量正确；
4. 首个注释组保留 `//go:generate go run ./gen`；类型/方法 doc 注释保留；
5. `format.Node` 回印结果与 gofmt 输出逐字节相等；
6. 语法错误源码被 `format.Source` 与 `go/parser` 拒绝；缺 package 子句被 parser 拒绝；
7. GC 后保留的格式化源码不变，AST 类型/字段计数仍正确；
8. `UAF_SEED` 派生 4 组不同规模配置（6–29 个类型）全部通过上述校验；
9. 最后一行 `ALL PASS l10_template_format_ast`。

## 失败判读

- 两次渲染不一致：模板在 range 内误用外层变量或 map 遍历顺序进入输出；
- gofmt 不幂等/回印不等：模板产生了 gofmt 无法稳定的结构（如错位注释）；
- AST 计数或字段名不符：模板 range/字段顺序错误；
- doc/directive 丢失：parser 未使用 ParseComments 或格式化时注释被丢弃；
- 负例未被拒绝：parser/format 未真正执行；
- `requires: [goast]`：无 go/parser、go/format 的构建用 `CAPS` 跳过本用例。

## 参数

- `UAF_SEED`：派生类型数、字段数与字段类型组合的种子，失败输出带 seed。

## 运行

```bash
go build -o /tmp/case ./cases/L10_codegen/l10_template_format_ast/*.go
UAF_SEED=1 GODEBUG=clobberfree=1 /tmp/case
```
