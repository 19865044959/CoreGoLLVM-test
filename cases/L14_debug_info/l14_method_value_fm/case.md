# 场景

绑定接收者的方法值 `w.Handle` / `w.Snapshot` 在运行期是 `-fm` 包装函数，通过 `reflect.ValueOf(f).Pointer()` 反查应得到 `main.(*mvWorker).Handle-fm`、`main.mvWorker.Snapshot-fm`；方法表达式 `(*mvWorker).Handle`、`mvWorker.Snapshot` 则保留普通方法符号。方法值经函数值间接调用后 panic，traceback 必须落到真实方法符号并带 `main.go:行号`。同时验证值接收者方法值在绑定时复制接收者、指针接收者方法值在调用时观察接收者最新状态。

## 期望行为

1. 指针/值接收者方法值的 funcval 名称分别以 `-fm` 结尾；
2. 方法表达式符号不带 `-fm`；
3. 绑定 `vv := w.Snapshot` 后修改 `w.seq`，`vv()` 仍返回绑定时的旧值；指针接收者 `cur()` 返回新值；
4. 方法值 panic traceback 包含 `main.(*mvWorker).Handle(`、`main.mvInvoke(`、`main.mvRun(`、`goroutine` 头与 `main.go:<行号>`；
5. 方法表达式调用 panic 的 traceback 同样包含真实方法符号与行号；
6. 两次 GC 后接收者 payload 与指针链仍有效，绑定时的值接收者副本不变；
7. 退出码 0，最后一行 `ALL PASS l14_method_value_fm`。

## 失败判读

- 方法值 funcval 无 `-fm` 后缀或名称错误：方法值包装函数符号表缺失；
- traceback 出现 `<autogenerated>` 或缺失方法符号：间接调用帧调试信息缺失；
- 值接收者方法值看到后续修改：绑定语义实现错误（复制了指针而非接收者值）；
- payload 字段错误：方法帧栈映射漏标接收者指针。

无随机路径；`UAF_SEED` 不参与逻辑。
