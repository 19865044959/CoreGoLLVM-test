# 场景

由同一个 `launchDumpWorkers` 批量创建 12 个 worker goroutine，全部阻塞在同一 channel receive 上。`runtime.Stack(buf, true)` 全量 dump 必须为每个 worker 给出 created by 归属（`main.launchDumpWorkers` + `main.go:行号`）、阻塞 worker 的真实符号与 per-frame 行号。模拟线上抓全量 goroutine 栈时定位“谁批量启动了这些协程”。`TORTURE_ROUNDS` 放大轮数。

## 期望行为

1. 1MB 缓冲区足以容纳全量 dump，不截断；
2. dump 中 `created by main.launchDumpWorkers` 出现次数 ≥ workers；
3. 每个 created-by 归属行后的位置行都是 `main.go:<行号>`；
4. `main.dumpWorker(` 出现次数 ≥ workers，且每个 worker 帧后都带 `main.go:<行号>`；
5. dump 包含 `main.main(`、`chan receive` 状态与至少一处 `main.go:<行号>`；
6. 放行后 errs==0，每轮 GC 后所有 worker payload 与 next 链仍有效；
7. 退出码 0，最后一行 `ALL PASS l14_goroutine_dump_created_by`。

## 失败判读

- created-by 缺失或符号为 `<autogenerated>`：goroutine 创建点调试信息缺失；
- created-by 行号为 0：创建点行号表缺失；
- worker 帧数不足：dump 被截断或阻塞帧栈展开错误；
- 放行后 payload 错误：阻塞帧栈映射漏标。

## 参数

- `TORTURE_ROUNDS`：轮数，默认 1，范围 1..8；每轮 12 个 worker；
- `UAF_SEED` 不参与逻辑。

## 运行

```bash
go build -o /tmp/case ./cases/L14_debug_info/l14_goroutine_dump_created_by/*.go
TORTURE_ROUNDS=4 GODEBUG=clobberfree=1 /tmp/case
```
